# 技术选型与架构方案

状态：提案，未实现。优先目标是单人/小团队、本地或局域网部署；先打通 30–90 秒短片，而不是一开始支持长片制作或完整专业剪辑。

## 1. 产品形态：Web-first，自托管优先

建议浏览器 UI + 本地/局域网服务。生成引擎可以在另一台机器，界面本身不需要 GPU。桌面版是后续包装方式，不应决定最初的数据模型。

| 方案 | 优点 | 成本/限制 | 决策 |
| --- | --- | --- | --- |
| 本地服务 + 浏览器 | 快速迭代、跨系统、访问局域网模型、容易共享同一项目服务 | 需要启动本地服务；浏览器不能随意读写全盘 | 第一版 |
| Tauri 桌面应用 | 文件选择、本地启动与分发体验更好 | 多平台打包、签名、Python/FFmpeg sidecar 生命周期额外复杂 | 核心稳定后再做 |
| 纯云端 SaaS | 分享和协作方便 | 云服务器无法直接访问用户 localhost/私有内网，需本地桥接；增加存储与鉴权成本 | 非第一版 |
| 原生专用剪辑 App | 极致媒体性能和系统集成 | 开发维护成本高，跨平台难 | 暂不选 |

Tauri 官方支持[外部程序 sidecar](https://v2.tauri.app/develop/sidecar/)，但“可以嵌入”不代表 Python 服务和视频工具能零成本完成跨平台打包。

## 2. 技术选型

| 层 | 建议 | 原因 |
| --- | --- | --- |
| 前端 | TypeScript + React + Vite | 工作台以交互为主，不需要先引入 SSR 与第二套后端 |
| UI 状态 | TanStack Query 管服务状态；轻量本地 store 管编辑状态 | 分开远端任务状态和本地拖拽/选中/撤销操作 |
| API | Python FastAPI + Pydantic | 便于连接现有 Python/ComfyUI 生态，契约校验清晰 |
| 数据 | SQLite + SQLAlchemy/Alembic | 单实例足够简单；团队多实例时再迁移 PostgreSQL |
| 工作器 | 独立 worker + 持久化 job 表 + 租约/心跳 | 长任务不依赖某个 HTTP 请求或浏览器标签页存活 |
| 事件 | SSE + 全量状态查询 | SSE 可断线重连；数据库是事实来源，不把内存事件当可靠日志 |
| 媒体 | 本地文件库、SHA-256、缩略图、代理视频 | 不依赖会过期的生成结果 URL |
| 渲染 | 服务端原生 FFmpeg/ffprobe | 输出、时长和帧率可验证；避免 MVP 浏览器 WASM 大文件开销 |
| 项目互换 | 自有版本化 JSON + 媒体清单；后续 OTIO 导出 | 项目包含生成语义；剪辑互换格式负责剪辑关系 |
| 节点画布 | 第二阶段可选 React Flow | 用于构思/依赖可视化，不作为时间线内部数据结构 |

[OpenTimelineIO](https://opentimelineio.readthedocs.io/en/latest/)表达剪辑时间和媒体引用，不是渲染器，也不把媒体自动打包进去。Premiere/Resolve 等互换需针对目标版本测试，不能声称支持 OTIO 就天然兼容所有软件。[React Flow](https://reactflow.dev/)适合节点交互，不是视频编辑引擎。上述组合是我们的工程建议，不是对竞品内部实现的推断。

## 3. 核心系统关系

```text
Browser workspace
        │ same-origin HTTP / SSE
Project API ── SQLite ── project versions / assets / jobs / timeline
        │
Persistent worker ── Provider adapters ── local / LAN / cloud generators
        │
Media library ── proxies / previews ── FFmpeg render worker ── exported film
```

浏览器只连接平台 API。模型凭据留在服务器；平台代理访问局域网服务，避免把每个模型接口的 CORS、密钥与文件 URL 暴露给前端。开发时由 Vite proxy 转发，发布时 FastAPI 或反向代理提供同源入口。

运行初期一个 API 实例、一个 worker。任务通过事务领取和租约实现恢复，按 `resource_group` 控制并发，而不是每个 provider 各开一条无约束队列。多个适配器如果共用同一 ComfyUI/GPU，必须共享同一资源额度。真正跨机器独立 GPU 才可并行。

## 4. 创作数据模型

```text
Project
├── StoryRevision
├── Character → CharacterVersion → reference assets
├── Location → LocationVersion → reference assets
├── Scene → continuity state
│   └── Shot → ShotRecipeRevision → GenerationJob → Take → MediaAsset
└── TimelineRevision → Track → Clip → pinned Take/MediaAsset
```

关键约束：

- 角色身份、服装/发型/道具状态、地点和整片风格分开管理。不能把所有内容塞进一个“人物提示词”。
- 镜头包含叙事目的、演员、场景状态、动作、构图、镜头运动、时长与声音计划。
- ShotRecipeRevision 保存实际渲染出的提示词、模板版本、引用资产版本、模型/工作流标识、参数、seed 与请求摘要。LLM 修改提示词必须可见、可撤回。
- Take 是一次生成产生的候选素材。新生成不覆盖旧 take；审批不等于删除其他候选。
- TimelineClip 固定引用 take ID 和媒体版本，不能随“镜头最新生成结果”悄悄变化。
- 时序关系和“前一镜头末帧作为下一镜头首帧”等生成依赖分别建模。依赖变更标记受影响配方为 stale，已有素材和剪辑保持不变；由用户决定重生成。
- 项目清单版本化并提供迁移；撤销/重做针对可序列化编辑命令，生成外部任务无法靠撤销假装取消。

## 5. 人物、场景与故事连续性

制作流程建议先准备角色参考组（正面、侧面、全身和服装）与地点参考，再为每个镜头生成/编辑首帧，人工批准后进行 I2V。模型支持多参考图、身份条件或 LoRA 时使用对应能力；不支持就展示降级，不暗中忽略。

Scene 记录光照、时间、服装、道具位置、人物位置等状态；Shot 记录 `state_in` / `state_out`、运动方向、视线和镜头轴线。LLM 可以协助拆分和检查矛盾，但用户审核的内容才进入正式分镜。

例如角色在镜头 1 把杯子放到左手，镜头 2 的首帧、提示词和连续性检查都应引用“杯子在左手”的状态，而不是只沿用角色姓名。

镜头衔接可选用已批准上一镜头的末帧；切到反打或不同景别时通常需要新的构图参考，不能机械复制末帧。固定 seed 不是身份一致性的保证。未来 VLM 可辅助标记问题，不能在 MVP 宣称自动保证一致性。

## 6. 时间线：先做好剪辑闭环

第一版一条主视频轨、旁白/音乐音轨和字幕层，支持排序、入出点裁切、空隙、替换候选 take 和撤销。转场等高级能力后续加入。用户看到的镜头编号与时间线 clip ID 分开，同一镜头可出现多次。

时间存储采用整数帧加有理帧率，禁止仅用浮点秒累积。MVP 固定项目输出 24 fps；导入其他帧率素材时记录源时间基并生成规范化代理。源时长以 ffprobe 检测为准，不以提交的 `duration` 为准。请求 5 秒的服务可能返回约 5.167 秒，需要明确裁切而不是静默改变故事节奏。

预览先采用规范化低分辨率代理；HTML video 的 seek 不应被称为严格逐帧精确。导出走后端确定性渲染，校验帧数、音画同步和字幕。FFmpeg 构建方式/编解码器有独立分发许可问题，发布安装包时需另行核查。MVP 不承诺实时多层特效或无限轨道。

## 7. 现有环境的接入边界

开发环境已做过本地 LLM 与局域网视频接口测试；具体部署地址与本地路径不提交公开仓库。这不是本平台已实现的集成。

- LLM 适配器：OpenAI-compatible chat；JSON 输出需验证，能力不支持时采用文本解析与用户审核。
- 视频适配器：T2V JSON；I2V multipart 图片 + prompt；返回 job ID，轮询状态，下载 MP4。服务没有 webhook 时使用有退避的轮询。
- 已知 I2V 是首帧条件输入，不是人物身份参考。`metadata` 只是业务记录，不能传人物参考给模型。
- 后端是共享串行队列，不让界面同时提交大量任务误以为能提升吞吐。
- 平台保存远端 job ID 后可恢复追踪；远端丢失任务应标为失败/未知并提示用户，不能自动重提可能收费的请求。
- 文生图/图像编辑尚需选择并测试 provider；可先手工上传参考与首帧，避免为等待图片引擎而阻塞最小闭环。
- WSL 服务中的 `127.0.0.1` 不一定指向 Windows 的服务；实际连通性、host 配置和监听范围要部署时验证。不得为方便连接就无鉴权监听所有网卡。

应用服务自身不要求模型完全 GPU 驻留。模型显存能力取决于模型、量化、上下文和并发；如果 LLM 与视频共用 16 GB GPU，必须调度互斥/卸载，不能承诺两者同时常驻。

## 8. 安全、可靠性与成本

绑定 loopback 为默认；局域网访问需要鉴权，公网需要 TLS。不要接收任意 URL 然后服务器无条件抓取：provider 地址允许由管理员配置，媒体下载限制到可信来源并阻止重定向绕过。媒体路径必须落在数据目录内，上传有大小/类型限制，导入 zip 防路径穿越。

密钥不进入项目导出或浏览器。插件第一版是经过审查的服务端适配器与数据清单，不加载任意用户上传 Python/npm 代码。LLM/生成提示不能授予执行 shell 的权限。

记录模型许可/服务条款、请求次数和已知费用；未知价格显示未知而非零。下载成功、媒体检测通过且配方快照落库之后，任务才能算 completed。项目导出包含素材清单与校验和；删除采用明确操作和可恢复机制，不让删除镜头自动清空其他镜头共享的素材。
